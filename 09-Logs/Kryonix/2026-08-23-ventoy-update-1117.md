# Update seguro Ventoy 1.1.16 → 1.1.17 (pendrive Inspiron DataTraveler)

Data: 2026-08-23
Agente: Aura
Repos afetados: nenhum (operação de infra local, não tocou código)

## Objetivo

Atualizar o Ventoy do pendrive Kingston DataTraveler 3.0 (57.7G) da Inspiron
**sem apagar os dados** da partição de dados (muitas ISOs e instaladores).

## Contexto consultado

- Estado real do disco `lsblk`, `blkid`, `sfdisk -d` (read-only)
- Release oficial 1.1.17 via `api.github.com/repos/ventoy/Ventoy/releases`
- Script de update no código-fonte `tool/VentoyWorker.sh` (linha 566: "Upgrade
  operation is safe, all the data in the 1st partition ... will be unchanged")

## Resultado principal — descoberta crítica

- O pendrive **já era um pendrive Ventoy** (layout bem formado: `sdb1` exfat
  "rag"/dados + `sdb2` vfat "VTOYEFI"/boot) com **versão 1.1.16** já instalada.
- O nixpkgs do Kryonix só tinha **1.1.12** (mais antigo) → usar `kryx shell -p ventoy`
  com `-u` teria feito **downgrade**. Decisão: baixar o installer oficial 1.1.17.

## Mudanças realizadas

- Baixado `ventoy-1.1.17-linux.tar.gz` + `sha256.txt` da release oficial GitHub.
- Checksum SHA-256 conferido: `7fb4ed08...c43805` = **VALIDADO**.
- Backup preventivo (read-only) em `~/.local/share/ventoy-update/`:
  - `sdb-partitions.backup` (layout GPT via `sfdisk -d`)
  - `sdb-head5M.img` (MBR + GPT header + core bootloader, 5MB)
  - `sdb2-vtoyefi.img` (partição ESP 32M completa)
- `umount` de `sdb1` e `sdb2`.
- `echo y | sudo ./Ventoy2Disk.sh -u /dev/sdb` → "Update Ventoy ... successfully finished."
