## Contexto

Bug latente crítico (achado #1 + #2 do audit estrutural 2026-08-03). `src/api/v2/mod.rs` declara router mas nunca é montado no router raiz. Resultado: features da UI que dependem de `/api/v2/kve/*`, `/api/v2/think/*` funcionam POR ACIDENTE via `src/api/mod.rs` que faz 2 `.nest(/kve, v2::kve::router())` redundantes.

## Causa raiz

```rust
// src/api/mod.rs:39-40 (atual)
.nest("/kve", v2::kve::router())      // ❌ dupla montagem
.nest("/think", v2::think::router())  // ❌ dupla montagem
```

`v2::kve::router()` injeta rotas `/health`, `/instances` etc. SEM prefixo. Como o `api/mod.rs` faz `.nest(/kve, v2::kve::router())`, o cliente bate em `/api/v2/kve/health` e funciona por acidente. Mas se o `v2/mod.rs` algum dia for montado, vai criar `/api/v2/kve/kve/health` (404).

`src/api/v2/mod.rs::router()` é código morto — `grep -rn 'v2::router\|v2::mod::router' --include='*.rs'` retorna 0 matches.

## Fix esperado

Em `src/api/mod.rs`:

```rust
pub fn router() -> Router<Arc<AppState>> {
    Router::new()
        .route("/capabilities", get(capabilities::get_capabilities))
        .route("/plan", post(install::post_plan))
        // ... rotas simples
        .nest("/virt", virt::router())
        .nest("/cluster", cluster::router())
        .nest("/console", console::router())
        .nest("/storage", storage::router())
        .nest("/v2", v2::router())      // ADICIONAR
        .merge(system::router())
}
```

E **remover** as 2 linhas redundantes:
```rust

.nest("/think", v2::think::router())  // DELETAR
```
