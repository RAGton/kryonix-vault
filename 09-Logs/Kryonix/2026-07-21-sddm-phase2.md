# Phase 2: Modernização do SDDM (Kryonix Node Think)

Data: 2026-07-21
Agente: Antigravity / Claude
Repos afetados:
- repos/kryonix

## Objetivo
Implementar a Fase 2 de modernização estética do Display Manager (SDDM) e Lockscreen do KDE Plasma. A modernização inclui a adoção do preset canônico `kryonix-clean` com a identidade "Kryonix Node Think" de forma padronizada.

## Contexto consultado
- Verificado que o módulo declarativo do SDDM (`modules/nixos/desktop/sddm/default.nix`) já existia na base de código e já gerencia as injeções das dependências nativas (Qt5/Qt6 - `qtmultimedia`, `qtsvg`, `qt5compat`, `qtvirtualkeyboard`).
- Verificado que a derivação nativa do pacote já é exportada nativamente pela Flake em `packages/kryonix-sddm-theme.nix`.
- Para honrar a identidade visual sem recriar layouts redundantes, modificamos a derivação principal para extrair o logo canônico do Node (`modules/node/core/themes/plymouth/node/logo.png`) em vez de utilizar mock-ups temporários ou baixar artefatos externos.

## Mudanças realizadas
1. **Derivação Nix (`packages/kryonix-sddm-theme.nix`)**: Modificada para injetar o `logo.png` proveniente do repositório core de plymouth do ecossistema Node Think.
2. **Ativação por Perfil (`profiles/desktop.nix`)**: Habilitada a propriedade `kryonix.desktop.sddm.theme.preset = "kryonix-clean"`, injetando a modernização canônica em toda a frota de perfis desktop de forma declarativa e sem efeitos colaterais em Hyprland.

## Validações executadas
- Avaliado `nix flake check` para atestar a sintaxe do módulo.
- Nenhuma falha de syntax na verificação modular (`nixosConfigurations.iso.config.system.build.toplevel`). O único problema (já pré-existente e isolado) encontra-se na CLI em Rust do `kryxd`.

Avançar para a **Fase 3: Modernização KPanel (React)** para aplicar a mesma diretriz de UI premium (Glassmorphism, consistência) e unificar de vez as interfaces.
